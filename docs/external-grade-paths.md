## Adjacent Moodle user provisioning

Moodle `enrol_sis` polls SIS provisioning commands and manages Moodle accounts, rosters, and memberships. It is not a grade feed, so it is tracked separately. Production Moodle is unchanged. Staging `enrol_sis` was rehearsed against the test mirror with a synthetic SIS student, signed user commands, a Moodle account, cohort and course membership, receipt handling, and idempotent replay. The test SIS provisioning key was restored byte-for-byte from its pre-rehearsal backup. Staging base URL and provisioning secret are unset, Dry run is enabled, and the scheduled task is disabled. The synthetic test account and grade-feed records remain isolated in test/staging for verification.

For the next authorized staging rehearsal, use the test SIS origin only, a test-owned `MOODLE_SIS_PROVISIONING_SECRET`, bounded synthetic command IDs, Dry run off only for the scoped run, and keep the scheduled task disabled. Restore the stage URL/secret and Dry run/task protections after cleanup. Never use the production Moodle user manager to poll test data.
