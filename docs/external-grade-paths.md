## Adjacent Moodle user provisioning

Moodle `enrol_sis` polls SIS provisioning commands and manages Moodle accounts, rosters, and memberships. It is not a grade feed, so it is tracked separately. Production Moodle is unchanged. As of 2026-11-27, staging `enrol_sis` is configured to `https://test.eagles.edu.vn` with the test-owned `.env.test` provisioning key, Dry run off, and the SIS sync task enabled. The enabled `moodle-staging-cron.timer` invokes only `\enrol_sis\task\sync` once per minute as `stage8567`; it does not run general Moodle cron tasks. Staging Moodle mail remains disabled (`noemailever=1`).

The test SIS API and staging Moodle completed synthetic account creation, encrypted password application, Eagles Club cohort membership, and course enrollment. SIS recorded applied receipts; replaying the same command receipt returned `duplicate=true` without adding a receipt, and an invalid HMAC was rejected with HTTP 401. The staging `A1 Movers` course has the unique SIS level ID number required by the provisioning contract. The test SIS provisioning queue has zero due, processing, or rejected commands, and `student_profile_enrollment` passes. In the 2026-11-28 run, a new student was created through the authenticated test admin form, all four provisioning commands applied, and the student signed into the test Student Portal. A read-only stage Moodle check confirmed the same generated password, SIS idnumber, active student role, Eagles Club cohort, and `A1 Movers` enrollment. The parent invitation checkbox had incorrectly defaulted on; the synthetic invitation was recorded as sent, then soft-bounced, with no delivery recorded. It was expired and its queued plaintext token was removed. The admin form now leaves this optional invitation unchecked by default. No production Moodle or admin/live SIS state changed. Historical pre-rehearsal notes below may describe earlier disabled states; the active configuration in this section is authoritative.

The staging Moodle user manager must poll only the test SIS environment. Do not use production learner data in `sis-test`, and do not point staging at the live/admin SIS or live Moodle. To pause test user provisioning, disable `moodle-staging-cron.timer`, enable Moodle Dry run, and disable the `enrol_sis` sync task. Keep the test SIS key in its test-owned environment file; never copy its value into Git, docs, shell history, or logs.
