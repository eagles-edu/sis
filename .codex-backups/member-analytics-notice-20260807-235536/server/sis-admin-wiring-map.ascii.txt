4) AUTH + ROLE GATE CONDITIONS
======================================================================

Public:
  - GET /admin/students[/slug]          (HTML)
  - GET /assignment-announcements/volatile/:token

Auth-required:
  - all /api/admin/* except login route

Role gates (enforceRoleAccess + assertCanManageUsers):
  - admin: read/write/manage users/permissions/service controls
  - teacher: read-only API generally, with explicit exception for
             queueing weekend-batch parent-report notifications

Session mechanism:
  - cookie session store (redis preferred, memory fallback)
  - auth routes: POST /api/admin/auth/login, POST /api/admin/auth/logout, GET /api/admin/auth/me

6) BACKEND-OWNED ASSIGNMENT FLOW
======================================================================

Current posture:
  - assignment templates and schedule ownership live in the backend canonical
    store/API.
  - /api/admin/dashboard emits:
      { levelCompletion, enrollmentOnlyLevels, currentAssignmentMeta }
  - the overview page renders API payloads and uses browser storage only for
    legacy import input and UX preferences.

Why this shape:
  - route/store responsibilities are now explicit.
  - the overview renderer is no longer a derivation engine for canonical rows.
  - reminder autofill can rely on currentAssignmentMeta without touching browser
    template state.

Remaining maintenance rule:
  - keep assignment-template API routes and dashboard payloads synchronized with
    the overview UI contract before expanding related reporting or reminder
    workflows.

7) RECOMMENDED MAPPING TOOLCHAIN
======================================================================

For this SIS stack (Node + single-page admin HTML + Prisma), a practical combo:

  1) Structurizr DSL (C4 model) [best for architecture ownership]
     - Keep Context/Container/Component views in versioned DSL.
     - Good for "page -> API -> store" and data-store boundaries.

  2) Mermaid (in docs/README) [best for quick flow diagrams]
     - Use sequence + flowchart diagrams close to code/docs.
     - Great for PR-level updates and low friction edits.

  3) dependency-cruiser [best for JS module wiring guardrails]
     - Auto-generates dependency graphs from code imports.
     - Add rules to prevent route/store coupling regressions.

  4) OpenAPI + Redoc (or Scalar) [best for backend IO contracts]
     - Formalize /api/admin endpoints and payload shapes.
     - Prevent drift between frontend assumptions and backend outputs.

Suggested adoption order:
  - Start Mermaid immediately (fastest value)
  - Add Structurizr for canonical system maps
  - Add dependency-cruiser to CI for wiring drift detection
  - Add OpenAPI spec for endpoint IO governance
